# A DoH RELAY FLEET — twenty DigitalOcean droplets, 2026-08-12
#
# WRITTEN INTO custom-throttle-list.txt FIRST AND MOVED HERE the same evening,
# with the section intact, once the classification was put to the user. It is the
# third move between these two files on 2026-08-12 — Top VPN and Bright VPN went
# the other way, from here to there — and the direction is the point: those are
# tunnels and shaping beats blocking, this is a DNS-changer and blocking beats
# shaping. The header's rule decided all three.
#
# WHY IT DROPS RATHER THAN SHAPES, which is the argument that moved it and is
# worth keeping because it inverts this pair of files' usual logic. Everywhere in
# the throttle file, a clean failure is bad: the client notices and hunts for
# another node. For a DNS-changer a clean failure is exactly what is wanted,
# because the fallback is not another node — it is the device's system resolver,
# which is ours and filtered. Dropping a resolver hands the device back to us.
#
# Shaping also barely touches it. A lookup is a few hundred bytes, so the
# 100 kbit/s cap costs it nothing; only the added latency and loss do any work,
# and slow-but-working DoH still resolves every name in custom-blocklist.txt.
#
# WHAT THEY ARE. Every one of the twenty presents a Cloudflare certificate on 443
# for CN=cloudflare-dns.com, and every one presents the IDENTICAL certificate:
# serial 4ED03304C46B87A8C2EB5569DB9EBA0C, valid Dec 31 2025 to Dec 21 2026, chain
# verifying cleanly. A DigitalOcean droplet does not hold Cloudflare's key, and
# twenty of them do not independently obtain one certificate, so these pass the
# TLS session through to Cloudflare's resolver rather than terminating it — the
# same relay mechanism as the a248.e.akamai.net and swdist.apple.com hosts in the
# throttle file, pointed at DNS instead of a CDN.
#
# Confirmed working, not merely listening: driven with a real DoH request
# (`curl --resolve cloudflare-dns.com:443:<ip> …/dns-query`) three of them —
# 138.197.89.51, 198.199.93.244 and 164.92.249.104 — returned HTTP 200 with valid
# answers for example.com. The other seventeen were fingerprinted by certificate
# only. None answers on udp/53, so DoH on 443 is the whole service.
#
# WHY IT MATTERS MORE THAN TWENTY ROWS. A handset pointed at one of these resolves
# entirely outside the router, which makes every name-based control we have inert
# for that device — the sinkholes, the imo names, the whole layer. That is a
# larger hole than any single tunnel node in either file, and it is invisible in a
# capture unless someone asks what the 443 flows actually are. It is also the
# reason the dns4all entry at the top of this file exists, and the same reasoning
# one layer up: a cached address does not need the name again.
