# CDN networks subject to a VOLUME QUOTA for low-trust pool devices. Nothing
# here is blocked or dropped, ever, and nothing here affects any other device.
#
# One AS number per line, `#` comments. Expanded to CIDRs at build time from
# ip2asn-combined.tsv, same as custom-lowtrust-asns.txt. An AS number the table
# does not know fails the build rather than silently contributing nothing.
#
# WHY THIS FILE EXISTS, and why it is not the ASN file next door. A tunnel
# client on the LAN moves bulk data through shared CDN edges by domain
# fronting. From 192.168.50.219-20260812-1324.pcap: 2,462 POSTs to `/` with
# Host: www.shoppeninegreen.com, sent to 95.100.170.59 and .57 — the genuine
# Akamai edge — every response 200 application/octet-stream, no User-Agent,
# 45.46 MB down and 3.01 MB up in 427 seconds. That is 0.85 Mbit/s sustained
# through an address this house depends on.
#
# Neither existing instrument reaches it:
#
#   - The ADDRESS cannot be taken. 95.100.170.0/24 serves the whole network,
#     which is why 95.100.170.42 sits on the lowTrustNeverCover tripwire.
#   - The NAME cannot be taken. www.shoppeninegreen.com resolves nowhere and
#     appears in no DNS answer in any capture — it exists only in a Host
#     header, so no resolver rule ever sees it.
#
# What separates the abuse from ordinary use is VOLUME, by more than an order
# of magnitude. Measured across every capture 2026-08-12 to 14: fronted cover
# names carried 46.0 MB, of which one port-80 conversation was 45.5 MB; every
# genuine Akamai and app hostname together carried 9.4 MB over two and a half
# days, largest single stream 5.3 MB. A budget of 50 MB burst refilling at
# 20 MB/hour sits an order of magnitude above the second and is exhausted by
# the first in about eight minutes.
#
# THE TRIPWIRE IS NARROWED FOR THIS FILE, not removed. The generator for
# custom-lowtrust-asns.txt refuses to build if a range covers any address on
# lowTrustNeverCover, and four of those nine — 95.100.170.42, 23.44.201.155,
# 185.93.2.251, 143.244.56.58 — are CDN edges, which are exactly what this file
# must cover. Those four are exempted here and the other five are still
# enforced, so the resolver, the STUN server and this operator's own hosts
# remain un-coverable by anything generated from this list. Verified: the
# current list contains precisely those four and none of the other five.
#
# Exempting even those four is safe here and ONLY here because of two
# properties that must both stay true:
#
#   1. A match shapes to the throttle tier. It never drops.
#   2. It applies to low-trust pool devices only, never house-wide.
#
# If either ever stops holding, the full guard has to come back.
