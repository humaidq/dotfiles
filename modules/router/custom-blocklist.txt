# === VPN Proxy Master (free.vpn.unblock.proxy.vpn.master.pro) ================
#                                                                  2026-08-30
# Static extraction: 6 dex, 38 MiB of bytecode. Not an app with a backend so
# much as a multi-protocol tunnel client — libxray.so (33 MiB), libopenvpn.so,
# libstrongswan.so/libcharon.so/libipsec.so, libss-local.so and libssr-client.so
# for Shadowsocks/SSR, libtun2socks*.so, libredsocks.so, and WireGuard by way of
# golang.zx2c4.com. assets/acp_connect_config_us.json names the protocols it
# actually offers: ipsec and issr.
#
# THE OPERATOR IS INNOVATIVE CONNECTING, and three independent strings say so:
# the Go modules are at git.inconnecting.com, support runs on
# inconnecting.zendesk.com, and the OAuth package is com.inconnecting.oauth.
# The whole VPN stack sits under co.allconnected.lib.* — AllConnected is the
# same group's SDK, so anything else carrying it is the same estate.

# --- WHY THIS SECTION WILL NOT STOP THE APP ---------------------------------
#
# Worth stating plainly rather than discovering later. There is NO node list in
# the package: the only addresses in 38 MiB of dex are public resolvers
# (1.1.1.1, 8.8.8.8, 8.8.4.4) plus 198.199.101.152, and no server list appears
# in assets. The nodes are fetched at runtime by co/allconnected/lib/serverguard
# from a base URL assembled at runtime — BASE_URL_FORMAT and
# BASE_URL_NO_SUB_DOMAIN_FORMAT, never a literal host — and libxray resolves
# through DoH (*dns.DoHNameServer, dohURL, getDohServers). So the transport is
# reached by address, over a name this file never sees.
#
# That puts it in the same class as the public-subscription nodes that
# custom-vpn-intel-throttle.txt shapes, EXCEPT that its list is private and
# signed, so fetch-v2ray-nodes.py cannot cover it — that script reads a public
# unauthenticated subscription, and this operator publishes none.
#
# 198.199.101.152 IS ALREADY BLOCKED in custom-ip-blocklist.txt, added
# 2026-08-28 from Rapid VPN's dex. Two unrelated VPN apps hardcoding the same
# DigitalOcean address is the useful finding here; see the note there.
