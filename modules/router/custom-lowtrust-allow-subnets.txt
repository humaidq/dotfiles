# Ranges the low-trust PROVIDER block must not swallow.
#
# This file exists because custom-lowtrust-asns.txt blocks whole hosting
# providers, and the apps this house has to keep working rent from the same
# providers as the tunnel nodes that list was built from. It is the runtime
# counterpart to lowTrustNeverCover in ip-blocklist.nix: that one is a
# build-time tripwire that FAILS the build when a generated range covers a
# listed address, which is the right answer for the handful of addresses the
# whole network depends on and the wrong one here — DigitalOcean genuinely does
# announce these, so a tripwire could only ever be satisfied by deleting the
# DigitalOcean entry and losing 537 collected nodes with it.
#
# SCOPE IS DELIBERATELY NARROW. A match here returns from lowtrust_policy at a
# point chosen so it overrides the ASN expansion and NOTHING ELSE:
#
#   * custom-lowtrust-ports.txt, the IPv6 reject and the QUIC drop are all
#     ahead of it and still apply;
#   * custom-lowtrust-subnets.txt is also ahead of it, so a hand-written block
#     still beats an entry here — hand-written is the more specific statement;
#   * forward_blocklists is a SEPARATE base chain on the same hook, so
#     custom-ip-blocklist.txt and the throttle list are untouched by this file.
#     An address listed here that is also a known tunnel node stays dropped.
#
# Addresses and not names. The obvious design was a names file on a resolver
# timer, like custom-lowtrust-stun-hosts.txt, and it cannot work for the case
# that motivated this: Botim's relays have no PTR, and smnvc.com and mncsv.com
# do not resolve from this router at all. The relay estate was found by probing
# certificates, so addresses are the only handle there is.
#
# HOW TO ADD: cert-probe the address before listing it. From the router,
#   openssl s_client -connect <ip>:443 -servername x </dev/null \
#     | openssl x509 -noout -subject -ext subjectAltName
# and record the subject in the comment. Note that `<no answer>` does not mean
# dead: output_blocklists stops the router itself reaching anything in
# custom-ip-blocklist.txt, so probe from somewhere else before concluding.

# nft-block-lowtrust-asn under the DigitalOcean entry, while
