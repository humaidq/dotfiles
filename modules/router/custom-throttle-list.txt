# Addresses to cripple rather than drop.
#
# THE SPLIT WITH custom-ip-blocklist.txt: VPNs and tunnels come here and are
# shaped; app estates — imo, BIGO/Likee, TikTok Live, the live-streaming and
# random-chat backends, DNS-changers — are dropped there. The reasoning is in the
# paragraph below: a dropped app backend just fails, where a dropped VPN node tells
# the client to try the next one. That file's header carries the same rule.
#
# Everything here is shaped to 100 kbit/s each way with 400 ms of added latency,
# 100 ms of jitter and 3% random loss, instead of being blocked outright. The
# point is that a tunnel behaves like a bad connection rather than a filtered
# one: there is no clean failure for the client to detect and route around, and
# an app that reconnects instantly when a node is dropped has nothing to react
# to when the node merely becomes miserable. The jitter matters more than the
# bitrate — 400 ms ± 100 ms reorders packets badly enough to make a tunnelled
# session unusable while leaving it technically connected.
#
# Same format and same guarantees as custom-ip-blocklist.txt: parsed at build
# time, so a typo fails the rebuild rather than silently shaping nothing, and
# overlapping entries are collapsed. Add live with `tempthrottle add <ip>`,
# which is cleared by the next rebuild — anything worth keeping belongs here.
#
# TEST SITE: https://ash-speed.hetzner.com/ — Hetzner's Ashburn speed test.
# Present so the shaping can be verified end to end from a LAN client: run the
# speed test and the result should be ~100 kbit/s with visibly awful latency.
# Remove it once the throttle is confirmed working.

# NOT EVERYTHING THROTTLED IS IN THIS FILE. One path is handled by a live rule
# that deliberately has no entry here, because the address it targets must not
# be in an address list at all.
#
# The tunnel operator is a paying Akamai customer: their domain has a real
# certificate provisioned on Akamai edge, so the client speaks ordinary HTTPS to
# a CDN address and Akamai forwards to their origin. The names are sinkholed in
# custom-blocklist.txt and the client reaches the edge anyway on a cached
# address, so the name layer does not stop it.
#
# The edge addresses cannot go in this file. 95.100.170.0/24 is shared Akamai
# edge — the same addresses serve Apple's iTunes certificate and TikTok assets
# to every other device on the LAN. Throttling them here would degrade those for
# the whole house. The client also moves between edge addresses freely
# (.42 -> .49 -> .51 observed), so pinning single addresses does not hold.
#
# So it is scoped to the client instead, as a live rule. Reapply after a reboot
# — this survives `nixos-rebuild switch` but not a restart, and nothing will
# indicate it is missing except the traffic going fast again:
#
#   ssh <router> 'sudo -n nft delete table inet flow_throttle 2>/dev/null;
#                 sudo -n /run/current-system/sw/bin/nft -f -' <<'RULE'
#   table inet flow_throttle {
#     chain shape {
#       type filter hook forward priority 1; policy accept;
#       ip saddr 192.168.50.220 ip daddr 95.100.170.0/24 counter meta mark set 0x2
#       ip saddr 95.100.170.0/24 ip daddr 192.168.50.220 counter meta mark set 0x2
#       ip saddr 192.168.50.156 ip daddr 95.100.170.0/24 counter meta mark set 0x2
#       ip saddr 95.100.170.0/24 ip daddr 192.168.50.156 counter meta mark set 0x2
#       ip saddr 192.168.50.219 ip daddr 95.100.170.0/24 counter meta mark set 0x2
#       ip saddr 95.100.170.0/24 ip daddr 192.168.50.219 counter meta mark set 0x2
#     }
#   }
#   RULE
#
# 192.168.50.219 added 2026-08-12 on capture evidence — see the Psiphon-meek note
# further down against 95.100.170.58. That handset ran 2462 POSTs to / on port 80
# across .57 and .59, 52 MB in about seven minutes. NOT YET APPLIED on the router:
# the rule above is the recommendation, and the routers were unreachable when it
# was written.
#
# Deliberately whole-/24 and both ports rather than `tcp dport 80`. Narrowing to 80
# would leave the handset normal HTTPS access to Akamai content, which is kinder to
# the device, but meek runs over 443 too and a clean failure on 80 is an invitation
# to move there. Shaping everything to the /24 leaves no working path to switch to,
# which is the same reasoning as the rest of this file.
#
# Delete the table first: `nft -f` appends to an existing chain rather than
# replacing it, so re-running without the delete silently doubles the rules.
# Mark 0x2 is what the tc filters in qos.nix steer into the throttled class, so
# this gets the same treatment as everything listed above.
#
# The cost, which is accepted deliberately: those two clients lose Akamai-hosted
# content generally, not only the tunnel. No other client is affected.

# IDENTIFICATION. The transport is plain SSH, and the client says so — SSH-2.0

# banner is different on almost every connection:
#
#   PuTTY_Release_0.68  0.69  0.70  0.71  0.72  0.74  0.77

# A real SSH client has one version string. Fourteen, cycling per connection from
# one device, is deliberate fingerprint randomisation, and it is the house style
# of the HTTP-Injector / HTTP-Custom / SocksIP family of tunnel apps — the ones

# That is also why the server list is this long and this diverse: it came with the
# config, and the app walks it on failure.
#

# matters because a port-based rule catches at most one of them:
#

#     Nothing on those ports parses: no TLS record header, no HTTP. tcp/179 is
#     BGP and tcp/553 and 554 are not in normal client use at all — the port is
